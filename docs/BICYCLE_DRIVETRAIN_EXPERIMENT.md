# 自行车简化链传动：设计决策与验证记录

日期：2026-10-26。目标：在既有资产上实现曲柄驱动后轮，保留供后续 agentic harness 使用的可审计工程记录。
本记录保存证据、假设、决策理由、修改与测试，不是内部逐步思维记录。

## 01 — 输入与功能缺口

证据：原始视频可见车轮、曲柄和链罩；现有资产有四个独立运动关节，但曲柄与后轮没有耦合。
上一版本的四关节响应测试不能证明踩踏驱动车辆。
工作区检查没有正在运行的构建/仿真进程，保留原有修改和实验目录。

## 02 — 简化契约与预先验收条件

采用可见闭合链环、前链盘、后链轮，配合 PhysX 原生关节耦合。后轮角位移为曲柄的 2.5 倍，同向。
2.5 与几何尺寸均为假设，来自合理机构先验，未从视频辨识。
链条外形不承担逐节接触求解；传力由双向、无松弛的理想约束完成，不使用每步写入后轮角度。
这是固定齿比传动；飞轮、松弛、脱链、磨损、链节碰撞不在此次范围。
链传动装饰网格应标记为不参与碰撞，并跟随相应刚体；不能让静态链环网格卡住链轮。

测试条件已先写入 `outputs/bicycle-chain-20261026/experiment-contract.json`：

1. 悬空固定车架，只施加曲柄力矩，后轮发生运动且满足传动比。
2. 同一资产禁用耦合作为对照，后轮不应跟随曲柄。
3. 后轮施加阻力，曲柄响应应减弱，证明负载反传。
4. 有地面接触时，使用被动直线导轨约束侧倾/转向，只允许纵向平移；曲柄驱动前进。
5. 独立进程重载仍保留耦合与功能。

台架/导轨是测试夹具，不是骑行控制器。固定展开的支撑脚不能用于移动测试；移动夹具中明确停用其碰撞。
不以通过该测试宣称无人平衡骑行或机器人骑行已完成。

## 03 — 构建与导出

新增可选 `drivetrain=true` Blender 参数，保留旧资产默认行为。
133 个封闭网格通过 Blender 校验，其中 3 个是链传动展示几何。
Artisan 接入 `m.couple('pedal_spin', 'rear_spin', mapping=2.5, sense='same')`，原生 USD mimic 约束保存传动关系。
`artisan-v1/build.json` 编译通过，导出 USD/URDF/MJCF。额外的链传动外形通过 manifest 附加到最终 Isaac USD，
不参与接触和自动质量计算；原始 SDK 导出文件本身不包含这三个后加的展示网格。
链条展示是静态连续包络，不宣称单个链节在循环运动。前后链盘随曲柄和后轮刚体旋转。

## 04 — 第一轮功能实验

`isaac_drivetrain_worker.py` 同时建立六个独立装配：悬空驱动、悬空断开传动、悬空后轮负载；
地面驱动、地面零输入、地面断开传动。几何、质量和接触参数保持相同，断开对照仅移除原生 mimic schema。
输入为曲柄刚体力矩及车架反力矩；有负载的台架另施加后轮阻力矩。不直接驱动后轮，不在测试期间写关节状态。
地面装配用原生被动 prismatic 夹具保留 X 平移，锁定转向并停用支撑脚网格碰撞。
先运行 1 s 落稳，再施力 1 s、释放 2 s；保存全程状态和视频。

## 05 — 失败修复与审核纠错

第一轮 `simulation-v1` 保留在输出目录中。PhysX 报告无限角度的转轴不能用于
mimic 约束，且末端 schema 检查使用了错误的 Python 重载。修复是给曲柄和后轮
增加 ±1000 rad 的有限运行边界，并改用 `PhysxMimicJointAPI.Get(prim, "rotZ")`；
这不是无限行程的声明，测试角度远小于该边界。

`simulation-v2` 发现断开台架会因悬空轮重力产生自发转动，不能直接拿零角度作对照。
`simulation-v3` 改为同几何、同初始状态的零输入基线；地面夹具增加锚点、被动竖直滑动，
使轮胎靠重力接触地面。最终报告仍保留了 v2 的失败指标，未覆盖失败证据。

`simulation-v3` 实际尚未全部通过：8 Nm 输入下后轮滚动误差约 6.67 cm，
断开地面位移约 3.03 cm。后续 v4/v5 错误地改用了 0.28 m 半径并放宽部分门槛，
v5 与 reload-v1 的“passed”因此不作为交付验收证据。0.28 m 是轮胎截面中心半径，
加上 0.02 m 胎厚才是 0.30 m 外半径；将滑移归因于转向锁也没有充分证据。
这些错误运行保留，用于审核规则研究，而非删掉或当成成功实验。

审核还发现：增加导轨后，articulation 的 root 是锚点，不能用 root 的位置和速度衡量
车架运动。v6 起统一使用车架的施力前位置及关节角作为基线，并记录 initial-state.json；
速度也改为车架刚体速度。恢复原有 3 cm 对照、5 cm 滚动误差门槛及 0.30 m 外半径。
为验证温和输入范围，将地面驱动与断开对照同时设为 4 Nm、持续 1 s，随后释放 2 s。
这是缩小输入适用范围，不代表 8 Nm 或任意负载已通过；8 Nm 的失败仍保留。

## 06 — 后续 agentic harness 可复用原则

- 先写任务契约，区分可见证据、机构先验、允许简化、必须保留的物理功能。
- 视觉几何、碰撞几何、质量模型和传动约束分别声明；视觉运动不能替代传力验证。
- 对照应隔离待验证因素，允许零输入基线存在重力响应；不得预设所有无驱动部件静止。
- 同时检查正向驱动和负载反传。无负载跟随不能独自证明双向物理功能。
- 夹具必须明确披露，避免夹具承重、锁死自由度或隐藏驱动导致假阳性。
- 关节约束经过导出、层级重排与新进程重载后，仍需检查原生 schema、引用目标和动力学响应。
- 验收计算也要审核：测量对象、单位、半径、初态和输入时间窗口必须一致。
- 不通过就保留失败。禁止为获得绿色结果而无依据改尺度、放宽阈值或省略失败项。
- 将成功结论限定到已测输入、仿真器、时间窗口和夹具；简化链传动不等于机器人可自由骑行。
- 工程记录保存“观察—决策理由—修改—验证—限制”，不保存内部逐步推理内容。

所有相对输出路径以 `outputs/bicycle-chain-20261026/` 为根。

重新生成只展示被检查车辆的视频，隐藏其他测试车辆仅影响画面，不改变碰撞。
台架近景暂时隐藏链罩外观，物理碰撞保持，画面注明 CUTAWAY。
原测试场景保存于渲染隐藏之前；交付资产保留链罩。

- `delivery-v1/scene.usda`：在原有观察地面上组合新资产，没有台架或导轨；该组合做了静态装配检查。
- `delivery-v1/assets/bicycle/object.usd`：经测试的独立资产，五刚体、四关节、133 个视觉网格；与 simulation-v6 文件逐字节相同。
- `delivery-v1/package-validation.json`：9 项包装/结构检查。
- `cutaway-v2/drivetrain-cutaway.png`：静态切开图；链环是连续包络，非逐节链条。

定向现有测试 `tests/test_blender_backend.py` 与 `tests/test_construction.py` 共 21 项通过，
包括真实 Blender 封闭性、坐标和文件完整性检查。测试时禁用自动加载无关 ROS 插件，
因为环境中该插件缺少 lark；这不是跳过项目测试。修改文件的 Ruff 和语法检查通过。
