# 可选的本地背景外观补全

更新：2026-10-28。按讨论缩小范围：只补齐操作区域之外的环境外观，采用可选的本地图像生成后端。本文保留设计范围；现已增加 `envcreator background` 及 Harness 可选配置，具体入口和使用方式见 [本地背景扩图](LOCAL_BACKGROUND.md)。逐次实验仍以运行记录为准。

## 现有流程与接入位置

`envcreator generate` 经 `harness/run.py` 构建和验证操作资产；可选的 `_background` 阶段另外执行背景处理。目前背景产物没有自动合成进主场景。

| 已有模块 | 本次复用方式 |
| --- | --- |
| `construction/background.py` | 复用真实背景 mask，排除机器人、工具和任务物体，避免生成背景中留下重复资产 |
| `construction/table.py`、`texture.py` | 保留桌面纹理融合与局部补洞；需要语义外观的空白区域交给生成后端 |
| `construction/reconstruction.py`、`train_worker.py` | 已有 COLMAP／3DGS 结果可提供参考图或渲染；新模块也可直接使用真实帧，不要求重新训练 GS |
| `harness/run.py:_background` | 已增加默认关闭的外观补全步骤，沿用阶段记录和失败状态，单独交付背景图 |
| `construction/background_scene.py` | 独立入口显式指定相机，在原 USD 上派生固定视角显示层；已有 Isaac 相机实测 |

本次不新增房间／家具网格、深度预测、碰撞体或交互语义。已有桌面、笔记本及工具等资产继续承担几何、接触与遮挡。

## 首选后端

已部署 **Diffusers + SD1.5 Inpainting**：输入背景参考图、补全 mask 和简短描述，扩展画布后生成缺失部分。该模型原本以 512×512 训练，使用半精度，按需启用 CPU offload；生成结束后释放模型，不常驻占用仿真显存。本机 16GB RTX 4070 Ti SUPER 的笔记本实例为 768×576、30 步，生成阶段含进程启动和加载共 8.56 秒，峰值分配／保留显存 3.59／4.04 GiB；数值仅对应本次条件。

模型资料见 [SD1.5 Inpainting 模型卡镜像](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-inpainting)，加载方式和卸载机制参考 [Diffusers 内存优化文档](https://huggingface.co/docs/diffusers/optimization/memory)。镜像声明与原 RunwayML 无隶属关系，接入时固定实际权重版本和哈希。模型路径单独配置，不调用 `VLM_API_KEY`，不引入新的模型聊天循环。

首轮只做背景图片扩图。需要转向四周时，再评估无缝全景生成；普通扩图结果不能直接改成 2:1 比例就当作正确全景。WorldGen 的全景生成组件可作后续候选，但其现有顶层类会加载深度模型，图生全景路径也使用深度，因此不直接把完整 WorldGen 当成首轮的轻量依赖。

## 使用流程与产物

```text
真实背景帧／现有 GS 渲染 + 背景 mask + 简短环境描述
                         ↓ 用户选择启用
              本地扩图：仅补缺失背景，保存固定结果
                         ↓
              背景图片 + 来源 mask + 生成记录
                         ↓
      渲染器背景／经验证的全景背景，或已有表面的纹理
                         ↓
                原有操作场景 + 更完整的环境外观
```

默认关闭；关闭时沿用已有流程，不加载生成模型。已有 `--background-generation-config` 复用同一 Harness 的可选阶段，独立命令为 `envcreator background`。

每次离线生成并固定一份结果，仿真中重复使用，不逐帧调用模型。真实背景保留区与待补全区分开处理；输出时将保留区原像素合回，接缝过渡区另作来源标记。移除任务物体后露出的背景属于生成补全，不能标成真实观测。

最少保存以下产物：

- 背景图片；后续具备对应后端时可保存全景。
- 真实保留、生成、接缝过渡及未知区域的 mask。
- 输入哈希、模型及权重版本、种子、提示词、分辨率和失败／修订记录。
- 场景中的背景引用、朝向和同视角加载截图。

实现集中在 `construction/background_generation.py`，由独立入口或现有 `_background` 调用。固定相机引用使用 `background_scene.py` 在原 USD 上叠加显示层，避免修改原场景组装逻辑；纹理和显示场景单独保存。生成依赖只在启用时加载。模型缺失或生成失败时明确记录该可选阶段未完成，保留原场景；不能把失败的扩图标成成功交付。通用 Harness 暂时单独交付背景图，不自动指定相机或替换主场景。

## 首轮实例：笔记本桌面

继续使用 `outputs/user-scene-assets-20261023/simulation/scene.usda` 的操作资产，参考 `outputs/user-video-build-20261022/` 的真实帧和背景结果；使用前核对现有版本和哈希。

本轮已使用真实视频帧与复核的外部背景 mask，保留原笔记本、瓶子、鼠标资产，补出周围环境并以固定相机背景板加载。实际 Isaac 相机及 120 步 PhysX 检查通过 7 项；80,418 个保留区像素未被改写。显示层显式隐藏原地面外观以露出生成地板，碰撞保留，但失去原地面阴影；相机尚未标定。记录见 `outputs/laptop-background-20261028-v1/实验记录.md` 与 `review.json`，截图在 `isaac-final/`，本轮没有运行机器人。

验证集中在实际加载效果：保留区是否被改写，背景是否重复出现笔记本／工具，边缘是否明显断裂，机器人相机是否能看到同一背景，以及关闭该选项后能否正常加载原场景。固定背景不能复制动态前景；笔记本开合、物体移动后不应留下背景副本。背景开关也不应改变已有物理设置；只作显示的背景应避免额外改动场景照明。

能力边界只有一点需要明确：**图片／全景可以补齐环境外观，但没有近景三维视差，也不表示恢复了原房间。** 首轮服务于桌前操作和背景完整性，不承诺绕家具或自由走动时仍然正确；背景没有可靠的深度、碰撞或新物体语义。

首轮输出放在独立的 `outputs/laptop-background-<run>/`，保存输入、生成图、来源 mask、记录和实际加载截图。现有资产与背景扩图分别保留，方便随时关闭或替换背景。

详细研究保留在 [生成式环境调研](GENERATIVE_ENVIRONMENT_RESEARCH_20261028.md)；其中大型三维生成流程仅供后续参考，不作为本轮依赖。
