# 生成式环境扩展：论文、实现与能力边界

调研日期：2026-10-28。阅读原论文、作者仓库、部分导出代码及官方产品文档；本轮没有安装模型、生成环境或运行第三方仿真实验。文中的速度、显存和效果均按来源注明，不能视为本机复现结果。

按最新讨论，本仓库先采用**可选、本地运行的背景外观补全**：补背景图片，后续按需支持全景，不新增房间网格或碰撞，也不要求重训 3DGS。具体接入见 [当前规划](GENERATIVE_ENVIRONMENT_PLAN.md)。以下完整三维环境方法保留为研究参照，不作为首轮依赖。

从学术和工程实现看，生成可浏览、可保存的静态视觉环境已有可借鉴的方案；从局部图像准确恢复原房间、保证任意视角或自动生成可靠机械交互，仍不能承诺。部分方法可导出 3DGS 和网格，并展示机器人导航；导出能力、导航示例与机械操作可用性需分别判断。

## 与当前 EnvCreator 的关系

现有 `construction/background.py` 准备真实背景监督，`reconstruction.py` 恢复相机并训练背景 GS；`table.py`、`texture.py` 处理平面纹理融合和局部补洞。这些模块尚未生成完整房间，也没有把背景 GS 自动合成进最终机器人场景。

```text
现有任务视频／多图
├─ EnvCreator 物体分支 → 桌面、笔记本等物理资产
└─ EnvCreator 背景分支 → 真实相机、背景 GS 和观测范围
                         ↓ 拟新增
                 可选本地扩图：补齐背景外观
                         ↓
                 固定背景图片／后续可选全景
                         ↓
             排除重复前景、接缝检查、模拟器相机重载
                         ↓
                 原有操作资产 + 补全后的背景
```

后端可以借用以下已有工作，不必自行训练一个新的世界模型。Qwen 的使用范围仍是 EnvCreator 内部的理解、规划与复审；第三方项目中的 Qwen-Image、Qwen3-VL 不等于本项目现有的 `qwen3.7-plus` API，不能因为同名就复用凭据或假定具备图像生成功能。ClawSpine 原生 DSH 与环境生成后端继续分开。

## 首轮的轻量候选

[SD1.5 Inpainting 模型卡镜像](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-inpainting)提供 Diffusers 的 `StableDiffusionInpaintPipeline` 入口，接受图像、文字和 mask，训练分辨率为 512×512。通过扩展画布并将新增区域标为待填充，可作为二维背景扩图基线。该链接是原模型的维护镜像，页面声明不隶属 RunwayML；后续固定实际权重版本及哈希。

[Diffusers 内存优化文档](https://huggingface.co/docs/diffusers/optimization/memory)提供半精度、模型 CPU offload 等机制。首轮优先低分辨率单张生成，结束后卸载；无需启动世界模型、深度预测或网格提取。尚未下载权重和实测显存，不能将本机 16GB 写成已验证兼容。普通补图也不保证无缝全景；扩图内容的空间布局和文字细节可能不可靠，真实保留区由输出合成保护。

## 完整三维环境的论文和实现

### 1. HY-World 2.0：完整的全景、扩展、重建和 GS 流程

[技术报告，2026](https://arxiv.org/abs/2604.14268)；[官方仓库](https://github.com/Tencent-Hunyuan/HY-World-2.0)。仓库还公告了产品端 HY World 2.1；本次核对的是公开的 2.0 论文和代码，不能将产品更新等同于相同版本的全部实现已公开。

生成链为 HY-Pano 2.0 全景生成 → WorldNav 相机轨迹规划 → WorldStereo 2.0 生成扩展视图 → WorldMirror 2.0 几何预测与 3DGS 优化。WorldStereo 使用全局几何和局部对应记忆改善跨轨迹的一致性。另有多图／视频重建分支；该分支不是自动补出真实未观测房间的证据。

本次核对到模型与推理入口，以及 [`gs/extract_mesh.py`](https://github.com/Tencent-Hunyuan/HY-World-2.0/blob/main/hyworld2/worldgen/gs/extract_mesh.py)。网格来自 GS 深度渲染后的 TSDF 融合／表面提取，不是带精确零件和制造语义的 CAD。代码提供有界和无界提取路径，“无界”属于表示和算法形式，不表示无限环境都真实或准确。

它最适合作为 EnvCreator 全环境生成的架构参照。需要保留的边界是：输入图像约束、尺度、隐藏区域和碰撞质量仍需独立核对；README 中“零误差控制、真实物理”等概括不能当作机器人操作实验结论。论文中的视觉、相机与重建基准没有替代本项目的抓持、摩擦或拆卸协议。

### 2. Lyra 2.0：长轨迹生成、回看记忆及三维资产

[论文，2026](https://arxiv.org/abs/2604.13036)；[官方实现](https://github.com/nv-tlabs/lyra/tree/main/Lyra-2)。

输入起始图像、相机轨迹和分段文本，先生成探索视频，再重建 GS。其三维记忆用于检索历史视图和提供空间对应；自增强训练用于减少自回归误差积累。重建模型针对生成图像的不完全一致性做了适配。公开入口输出探索视频、相机等中间数据以及 GS。

论文第 4.4 节描述从 GS 提取网格，第 5.5 节展示导入 Isaac Sim 的机器人导航与交互。因此不能笼统说生成式环境都不支持仿真。但这没有证明生成场景具备正确质量、关节、工具接口或可拆装连接。本次没有复现它的网格提取和 Isaac 示例，也没有验证其与本仓库固定运行环境的兼容性。

论文第 6 节明确限制：主要针对静态环境，没有显式建模动态场景；训练数据中的曝光变化会被带入生成并造成 GS 瑕疵。长轨迹一致性有所改善，不等于返回任意位置都没有变形，更不等于背面结构真实。

### 3. VistaDream：适合对照现有 GS 流程的多视图补全

[论文，ICCV 2025](https://arxiv.org/abs/2410.16892)；[官方仓库](https://github.com/WHU-USI3DV/VistaDream)。

先由外扩图像和估计深度建立粗三维框架，再用 RGB-D 补图填充新视角，随后使用 Multi-view Consistency Sampling 约束扩散采样中的多视图一致性，输出 Gaussian 场。仓库还提供稀疏多图入口，以 VGGT 重建作为框架。

“Training-free”表示无需为该流程重新训练基础模型，仍需预训练扩散、深度和语义模型。它适合研究如何让几张生成图像共享同一个场景，而不是只在输入图附近各自看起来合理。

论文附录 A.5 展示了近处物体因为单目深度不准而严重变形。笔记本、桌边和机械工具恰好属于本项目在意的近景，不能交由该类生成结果替代已有精确操作网格。仓库新分支的深度后端升级与期刊扩展，本轮未做运行验证。

### 4. WonderWorld：交互式增量扩展的较早代表

[论文，2024](https://arxiv.org/abs/2406.09394)；[官方仓库](https://github.com/KovenYu/WonderWorld)。

从一张图开始，用户指定新视角及内容，生成并增量加入分层 GS，形成连接的可浏览场景。可以借鉴其“渲染已有区域、仅生成新区域、保存版本”的组织方式。

论文 Limitations 明确说明场景只有朝向相机的表面，没有生成物体背面，因此新视角范围有限；细碎结构在换视角后会出现空洞和漂浮物。作者将其定位为交互式世界原型方法。它直接说明：**能继续向前扩展，不代表能绕到每件物体背后检查。**

### 5. WorldGen：可参考的全景与三维转换实现

[作者仓库](https://github.com/ZiYang-xie/WorldGen)；[项目页](https://worldgen.github.io/)。仓库 TODO 中仍保留技术报告发布事项，本次将其作为工程实现，不按已充分发表和验证的论文结论使用。

入口为 `WorldGen(...).generate_world(...)`，支持文字或单图，输出 GS 或网格。已阅读 [`src/worldgen/worldgen.py`](https://github.com/ZiYang-xie/WorldGen/blob/main/src/worldgen/worldgen.py)：基础路径主要是全景生成／填充 → 全景深度 → RGB-D 转 GS／网格；另有实验性 Sharp 路径和可选背景补图。

完整三维表示可以稳定重复渲染，但单个全景加深度仍主要描述各方向首先看到的表面，不能等同于完整的物体背面和房间体积。README 中“360°一致探索、闭环”需按此表示理解，不能扩展成任意六自由度漫游的保证。仓库也仍列有改善不可见区域补图的待办。

其低显存模式可作后续候选，本轮未下载模型或确认实际峰值显存、速度、质量及导出兼容性。代码中的顶层构造函数会加载深度模型，`i2s` 的 `generate_pano` 本身也要估计输入深度；仅改调用方法名不能去掉这项依赖。当前外观补全先使用独立二维后端，未来若借用它的全景组件，需要明确组件及基础权重的实际依赖。

### 6. Marble：已有服务化导出，但仍有明确范围

[官方文档](https://docs.worldlabs.ai/)；[导出格式](https://docs.worldlabs.ai/marble/export/specs)；[网格限制](https://docs.worldlabs.ai/marble/export/mesh)。

支持文字、单图、多图、全景、视频和粗结构输入；可导出 PLY／SPZ GS、简化 GLB 碰撞网格及高质量 GLB 视觉网格。它适合作为外部效果参照或后续可选服务，不是本项目已经接入的 API。

官方将碰撞网格和视觉网格分开，明确说明薄结构、透明／反射表面、覆盖不足处会有孔洞、浮块和不均匀几何。单图指南不推荐缺少空间上下文的物体特写；视频指南推荐静态场景、固定焦距和曝光，并覆盖 180°–360°。只有笔记本裁剪图会丢失房间布局条件。

[Expand 文档](https://docs.worldlabs.ai/marble/create/prompt-guides/expand)也限制了可扩展区域、模型版本及方向：当前说明不支持向上／向下扩展，Marble 1.1 Plus 生成的世界不能使用该扩展功能。不能仅根据品牌名称假定所有模型支持相同操作。费用和账户权限未查询，未向其上传本项目素材或发起生成请求。

### 另外两类值得区分

- [Gen3C](https://github.com/nv-tlabs/GEN3C)、[Voyager](https://github.com/Tencent-Hunyuan/HunyuanWorld-Voyager)利用三维缓存／RGB-D 视频改善相机控制和场景扩展。它们提供生成视图或几何中间量，但不能仅凭一段相机可控的视频宣称已交付稳定的物理场景。
- [Infinigen](https://github.com/princeton-vl/infinigen)通过程序化几何和布局生成房间；适合提供明确的环境结构与随机化，不负责从局部桌面图忠实恢复同一个原房间。[整场景仿真导出文档](https://github.com/princeton-vl/infinigen/blob/main/docs/source/ExportingToSimulators.md)明确该入口导出无关节 USD，已测试范围为室内 Isaac Sim；另有独立 articulated 分支，不能混为同一个导出能力。

## 对本项目需要明确的能力边界

| 需求 | 当前研究／实现支持到哪里 | EnvCreator 的处理方式 |
| --- | --- | --- |
| 补出桌面之外的墙面、地面、家具 | 已有生成完整视觉环境的实现 | 可作为新增背景能力，保留多个合理候选 |
| 从一段桌面视频恢复原房间背面 | 未观测区域存在多解，生成结果不能证明真实 | 标记合成／推断，不写成重建事实 |
| 360°查看 | 全景和三维表示已支持 | 首轮二维扩图不自动具备此能力；后续全景区分原地旋转与移动相机 |
| 任意六自由度移动、无限扩展和返回 | 记忆方法改善一致性，仍不能保证所有位置质量 | 声明实际检查过的相机活动范围，不预设通用米数／角度保证 |
| 保存固定场景并重复渲染 | GS／网格可以做到，明显强于只有视频的输出 | 固定模型、随机种子和资产版本，避免每次观察重新生成世界 |
| 精确保持现有笔记本和工具 | 普通生成模型没有普遍的几何／像素不变保证 | 独立引用既有操作资产；保护区域和背景前景排除由代码检查 |
| 使用真实米制尺度 | 单图深度和世界生成先验不能当作尺寸测量 | 沿用尺度锚点与显式坐标变换，保留估计和假设 |
| 机器人导航和障碍碰撞 | 部分论文和产品已有 mesh／Isaac 示例 | 碰撞代理需另行检查地板连续性、穿插及机器人通行，不直接接受提取网格 |
| 抓持、开门、机械拆装 | 场景 GS 或整体三角网格没有自动提供关节、力学和装配语义 | 继续由 EnvCreator 的部件、约束与工具验证模块负责 |
| 真实材质、摩擦、重照明 | 外观可能烘焙了原照明；生成颜色不是物理参数 | 分开记录 RGB、渲染材质与接触参数，不反推成测量值 |
| 动态操作过程中背景正确 | 静态环境生成最成熟；动目标容易留影和重叠 | 将机器人、手、工具及任务物体从背景中剔除；首轮背景不提供生成深度，前景仍由既有场景渲染 |
| 直接用于机器人训练并提高真实表现 | 可以产生视觉变化；效果仍取决于后续任务实验 | 定位为环境资产／外观随机化来源，不预先承诺训练或 Sim2Real 增益 |

固定三维场景解决的是“同一份资产可以重复观察”，不自动解决“几何正确、原图保真、真实尺度和物理语义正确”。生成 GS 也可能把多视图之间不一致的内容固化成浮块或重影。

## 本机部署范围

本次只读确认本机为 RTX 4070 Ti SUPER，显存 16376 MiB。以下是上游资料，不是本机测量：

| 项目 | 上游说明 | 对本机的含义 |
| --- | --- | --- |
| SD1.5 Inpainting + Diffusers | 提供图像／mask 入口和半精度加载示例；Diffusers 支持 CPU offload | 当前首选二维基线；没有本轮实测显存或速度数据 |
| WorldGen | 低显存生成约 10GB；代码会在低于 24GB 时启用低显存路径 | 后续全景候选；其顶层类和图生全景仍使用深度模型，非纯二维最小依赖 |
| VistaDream | 测试环境为单张 RTX 4090 | 不能据此承诺 16GB；需独立调整及验证 |
| WonderWorld | README 要求 48GB | 官方原配置超出本机显存 |
| Gen3C | 完整卸载配置所记录峰值约 43GB，测试 A100／H100 | 官方记录超出本机显存，不先作为本机基线 |
| Voyager | 540p 最少约 60GB，推荐 80GB | 官方配置超出本机显存 |
| Lyra 2.0 | H100 80GB 上每 80 帧约 9 分钟；DMD 约 35 秒 | 这是视频生成步骤的数据，不是完整环境生成时间，也不是最低显存声明 |
| HY-World 2.0 完整生成 | 推荐至少 4 GPU，测试 8×H20；还需独立 VLM 服务 | 完整官方流程没有本机单卡 16GB 可直接运行的依据 |
| Marble | 外部服务，可导出资产 | 不占本机生成显存，但资产渲染和导入仍需本地验证；本轮未调用 |

HY-Pano 的适配器文件大小或参数表不等于完整生成模型的显存；生成速度也常不包含全景、下载、GS 优化、网格提取和模拟器导入。不能把“几秒生成”直接写成 EnvCreator 完整交付耗时。

公开源码与模型权重的许可分别保留。Lyra 2.0 代码为 Apache 2.0，权重使用 NVIDIA Internal Scientific Research and Development Model License；HY-World 2.0 使用自己的 Community License。后续若发布模型、服务或衍生数据，再针对实际版本核对条款，本轮不将其统称为无条件开放的依赖。

## 对上一版规划的具体修订

1. **先用本地二维补图。** 优先评估 Diffusers + SD1.5 Inpainting，默认关闭，使用本地模型路径和低分辨率单张生成；未安装、未运行。WorldGen 全景组件仅作后续候选，大型三维流程保留为研究参照。
2. **复用背景分支和真实参考。** 从原视频或已有 GS 渲染选择带桌边及周围空间的图像，保留真实背景，生成缺失区域；移除背景中的笔记本、机器人及工具副本。无需增加布局推理、深度估计或 GS 训练阶段。
3. **交付背景图片及来源记录。** 使用渲染器背景、经验证的全景，或已有表面的纹理；不新增环境网格与碰撞。保存 mask、模型版本、种子和输入／输出哈希，不逐帧重新生成。
4. **接受外观补全的范围。** 图片／全景没有近景三维视差，不支持由背景直接推断深度、障碍或新交互对象；首轮不要求自由漫游。加载时检查接缝、重复前景、机器人相机可见性，以及原资产物理设置未因背景开关改变。
5. **先做笔记本桌面的一份候选。** 保存原场景与背景开启后的同视角截图，以及真实／生成区域对照。暂不把导航、完整房间恢复或机器人训练效果作为本轮目标。

上述步骤仍由 EnvCreator 提供生成与验证能力，原生 DSH 负责调用相关插件及记录；本次不新增外层模型循环、不动 ClawSpine 模型配置，也不复用 VLM 凭据发起环境生成请求。
