# SceneCreator 多场景重建与资源调度长期规划

记录日期：2026-11-09。用户明确要求本条只纳入长期规划，本轮不实施，不启动新并发作业，不修改当前并发配置，不制作镜像。

## 目标与现有基础

最终部署环境不限于当前单卡约 16 GB 显存。目标是在更高性能的单机、多卡乃至同一硬件集群上，持续处理多个视频和图片场景，并发执行工具调用、资产生成和背景重建，提高整机吞吐和利用率。

现有基础为 SceneCreator 组件目录、显式来源角色、独立组件进程、不可变产物与哈希、DSH 原生调用身份、CPU/GPU/内存/磁盘与进程采样。当前 Jobs 只有固定并发信号量，不是显存调度器；固定并发数不能保证资源使用合理。现有实现不宣称具有集群调度、容器执行或动态 GPU 分配能力。

## 工作流并行边界

SceneCreator 管理感知、背景重建、Blender、OpenUSD 和 Isaac 验证组件，旧构建继续支持 Artisan。DSH 负责任务决策，Infra 负责作业的资源准入和执行。

单个场景完成语义与前景/背景隔离后，可在输入版本固定的前提下展开互不依赖的分支：

```text
图片/视频 → 解码/采样 → SAM + VLM → 固定感知版本与前景/背景路由
                                  ├─ 前景对象 A：证据 → 结构 → 几何 → Blender/OpenUSD → 验证
                                  ├─ 前景对象 B：证据 → 结构 → 几何 → Blender/OpenUSD → 验证
                                  └─ 背景：观测准备 → COLMAP → 3DGS → 真实总览
                                          ↓
                              在依赖完成后汇合为场景与交付
```

不同输入场景之间也可并行；某个场景的 3DGS 不应占住所有低负载工具。依赖未完成、来源版本变更、跨分支身份不一致时，不能仅为并发而跳过约束。物理验证需要单独声明运行条件，不能继承其他资产或旧版本的通过结论。

## 资源测量后再准入

先用实际作业建立组件资源记录，涵盖输入分辨率、视频帧数、掩码/对象数量、COLMAP 特征规模、高斯数量、训练配置和渲染输出尺寸。记录 GPU 显存峰值、计算占用、CPU、系统内存、磁盘吞吐、初始化耗时和总耗时。整机占用与可归属进程占用分开；无法可靠归属的资源保持未知。

调度器据实际可用资源和历史峰值进行准入，并保留容错空间；按阶段调整资源预留。GPU 空闲百分比不能单独作为放入新作业的依据，显存、系统内存、CPU 和 I/O 都可能先饱和。冷启动/模型驻留也计入预算。

同卡并行、多卡分配、CPU 与 GPU 流水交叠分别评估。MPS、MIG 或其他隔离机制只在硬件/驱动支持且实测收益明确时采用。达到高利用率的同时，保留交互作业响应、队列公平性、取消能力和失败恢复，避免长视频永远挤压短任务。

## 镜像与执行后端

为依赖冲突或负载较重的组件设计独立的容器执行环境，优先考虑 3DGS、COLMAP、Blender 和 Isaac。OpenUSD 与旧 Artisan 兼容后端可各用自己的解释器。GPU 分配、显存控制与作业准入由宿主或集群调度。

执行接口保持统一：明确的输入产物、配置、输出位置、事件、资源声明、取消、退出状态和检查点。容器内外沿用原 DSH call ID 与 SceneCreator run ID。记录镜像 digest、代码/依赖版本、驱动和 CUDA 条件，凭据运行时注入，不写入镜像或可下载产物。

输入按只读产物挂载，输出隔离；大体积视频、相机数据和模型减少重复复制。缓存按内容哈希、模型版本及影响结果的配置区分，不能把不同输入或旧语义的产物错误复用。共享模型服务和长驻 worker 只在取消、身份隔离、显存驻留和实测吞吐均可控后考虑。

## 后续实施顺序

1. **测量现有串行任务**：使用电脑、自行车及不同规模图片/视频，形成真实资源记录，先确定瓶颈。
2. **组件资源声明与准入**：沿用现有组件接口，加入调度需要的资源信息、设备分配和有界队列；保持串行回退。
3. **单场景分支并行**：先验证前景对象与背景分支，以及不同前景对象之间的并行；依赖汇合与过期状态必须正确。
4. **重组件镜像**：保持同输入/配置的行为一致，再替换进程执行后端；检查取消、GPU 释放、失败和检查点恢复。
5. **多场景、多卡/单硬件集群**：引入设备池和多节点产物定位，混合视频与图片作业，验证稳定吞吐与交互响应。
6. **按实测优化**：比较串行、保守并行和调优并行，依据结果调整模型驻留、批处理、分辨率、I/O 与作业排序。出现 OOM、显著争用或质量变化时收紧准入，不能只增加并发数。

DSH 页面届时展示场景队列、分支进度和资源归属；用户仍以自然语言与简要结果交互，调度参数与容器日志留在 Infra 详情中。
