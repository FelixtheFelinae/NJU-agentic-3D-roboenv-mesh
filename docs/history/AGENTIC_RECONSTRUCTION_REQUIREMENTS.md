# Agentic 重建目标与后续规划

记录日期：2026-10-26。来源：用户本轮明确要求。本文记录需求与建议，未实现以下规划。

后续同日用户调整执行顺序：先接入 Blender 建模后端，暂不实施 agent 决策或自动修复。
当前后端实现及运行证据见 [BLENDER_BACKEND.md](../BLENDER_BACKEND.md)；下文闭环仍是长期规划。

## 用户确认的优先级

- 输入视频，自动解析、生成、审查并修复可交互的场景资产，减少逐次由用户发现重建失败。
- 外观应保留物体可辨认的真实轮廓、主要部件、相对比例和曲面形态；不能以粗糙基本体拼接且形态明显错误的结果作为最终资产。
- 不追求照片级纹理或逐项精确实物标定。尺度可估计，质量、摩擦、阻尼、关节力矩等可使用合理假设并明确来源。
- 交互应由物理求解器中的接触、刚体和关节动力学产生；修改姿态、写入关节角或播放动画不能作为力驱动交互通过的证据。
- 后续通过有约束的域随机化覆盖物理参数变化、扩大训练数据；不将精确扭矩辨识作为当前前置任务。
- 当前不需要加入机器人。沿用 Artisan Coding / Review 的分工，考虑 Blender MCP 等更强的曲面建模工具。
- 本轮只规划、记录需求，不修改代码、不安装或连接 Blender、不重跑重建。

## 当前可确认的不足

现有 `asset_agents.py` 已有独立 Coding / Review 上下文、候选与证据哈希绑定，以及
topology / hinge / clearance 类型化 QA；不能说项目完全没有审查。
这些检查不足以自动拒绝主要形态失真的资产；Review 仍需直接核对原始视频证据，
不能仅以蓝图作为真值，否则错误蓝图会得到错误模型的自洽通过。
白桌修订报告中的编译通过、8/8 物理检查和 3/3 重载检查，不代表外观或全部交互通过。
精确力矩未标定和耳机形状错误属于不同问题，不能用允许参数近似来放宽几何验收。

## 建议的闭环

视频证据 → 部件与交互蓝图 → 选择建模后端 → 候选资产 → 独立多层验收
→ 结构化失败诊断 → 选择修复工具 → 局部重建与回归验收 → 场景组装与最终导出复检。

验收分开记录：

1. 证据：分割是否切掉部件、跟踪身份是否混淆、可见视角是否充分、尺度来源是什么。
2. 外观：逐物体近景、多角度原图/渲染对照、轮廓与部件比例、灰模轮廓、贴图附着。
   可靠相机与分割条件下计算轮廓/关键点误差，并与 VLM 部件级审查交叉核验；
   未观测背面标注为假设，不能要求其匹配不存在的证据。
3. 交互：任务需要的部件划分和自由度、碰撞代理与外观表面的偏差、关节限位、
   外力推动/拿起/开合后的响应、释放后的行为、穿透和数值稳定性。
4. 场景：尺度和坐标一致、接触位置、物体摆位、最终 USD 在独立进程重载后的表现。

外观、交互、稳定性分别设门槛，不能以加权总分掩盖某一项失败。
近景和源视频对照必须作为验收证据，整场景远景不能替代。
审查输出需包括对象/部件、失败类型、原图与渲染证据、置信度、建议修复动作、影响的检查。
Coding 不可改验收标准或证据；审查结果绑定候选版本，修复后作废受影响的旧通过记录。

失败路由示例：

- 缺失耳罩/盒盖：重新选帧与分割，复核部件蓝图，再建模。
- 轮廓和比例错误但证据完整：保留证据，调整几何参数或切换曲面建模后端。
- 漂浮贴图：检查 UV、面集和刚体父子关系，重新渲染运动状态。
- 灰模正确但纹理含旧阴影/遮挡：重新挑选纹理来源或使用简化材质。
- 关节动画能动但受力不动：检查关节定义、驱动/摩擦假设与外力测试方法。
- 碰撞或稳定性失败：修改碰撞分解、质量惯量或求解设置，再验证外观接触一致性。

设置每资产的尝试/计算预算，保留最佳候选；连续无改善时切换方法，不能无限重试。
证据不足、评审持续分歧或预算耗尽时输出明确未通过原因，必要时只向用户请求缺失证据。
该流程降低人工复审频率，不承诺 VLM 零漏检。

## Blender 的定位

Blender 作为几何、材质、渲染后端接入现有构建环；MCP 提供控制接口，并非自动重建算法。
头戴耳机优先用可变截面曲线建立头梁、曲面耳罩与耳垫，并保留连接件和间隙；
充电盒建立圆润外壳、内腔和独立盒盖；功能相关的转轴再映射为物理关节。
避免不加判断地增加不可见机构，或把全部视觉细节都做成独立刚体。

视觉 mesh 与碰撞 mesh 分离，但必须保持接触表面、空隙和运动空间的一致。
Blender 输出部件 mesh、材质、局部坐标与接口数据；现有资产适配层负责物理语义和仿真验收。
原型阶段可用 MCP 交互检查；规模化运行保存可重放的 Blender Python 建模脚本、参数、种子、
工具版本和资产版本，使用后台 Blender worker 批量构建渲染。
程序化模板不适用时，可路由到多视角重建/生成 mesh 后整理，但必须通过同一验收。
3DGS 的外观表现不能替代可交互对象所需的碰撞与部件结构。

## 实施顺序（待后续授权执行）

1. 将已有失败变成固定审查样例：耳机轮廓失真、盒体粗糙、平板贴图漂浮、关节假交互。
   同时包含可接受近似的正样例，统计漏检、误报、人工介入率和每资产成本。
2. 接入 Blender 建模后端，以耳机作首个曲面资产试点；实现物体级特写和源视频对照。
3. 打通失败报告到选工具/修复/复审的闭环，随后复用到平板和充电盒。
4. 在合格资产上增加有约束的参数随机化与批量交互数据生成。

随机化保持质量和惯量物理有效、几何与惯量变化相关、静动摩擦关系合理、关节范围一致，
每组采样参数仍要通过适用的接触/交互测试。允许动作结果变化，不要求每次停在同一角度。

首个里程碑：无需用户逐轮指出问题，系统能在已知失败样例中主动发现并定位缺陷，
选择合理修复并生成可追溯的通过证据；不以“成功运行完流水线”为完成标准。
