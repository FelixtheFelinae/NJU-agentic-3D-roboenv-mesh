# 电动螺丝刀：DSH 工具生成与机器人使用实验规划

日期：2026-10-28。本文安排后续实验；不将计划内容记为已完成结果。

## 机器人接收的任务

采用用户给定的原始自然语言，正文保存在 [public-task.md](public-task.md)：

> 让机器人抓握这把螺丝刀 尝试拧松并取下螺丝

任务通过 ClawSpine 原生 DSH 的用户消息入口原样提交。机器人依据允许的观察，自行决定抓握、对准、电机使用和取出过程；提示中不额外指定左右手、动作顺序、目标坐标、转动圈数或参考轨迹。下面的阶段用于开发和隔离问题，不替换这条完整任务，也不作为必须照做的模型操作脚本。

当前场景仅完成抓取/对准准备，完整任务仍需电机接口、动态紧固件及取出行为。理想夹持属于单独的开发实验，不算完成这条任务中的自主抓握。结果需分别记录实际抓持、螺纹解除和完整取出；仅达到 `thread_clear` 不能称为已取下螺丝。

## 已有实现与实验基础

执行关系为：

```text
原生 DSH 模型与会话
  → integration/tool_plugin.mjs：注册 EnvCreator 相关工具，关联 native 调用 ID
  → integration/tool_backend.py：调用固定后端操作，记录前后状态与失败
  → harness/tooling.py：官方参考收集、工具生成、功能验证及报告核对
      → tools/electric_screwdriver.py → Blender → Artisan → 工具 USD
      → tools/isaac_screwdriver_worker.py → Isaac PhysX → 实测轨迹与报告
  → 插件结果返回 DSH，原生历史保存模型调用与反馈
```

Blender 根据声明式配方生成网格，Artisan 编译部件、关节与物理资产，Isaac 执行受力和运动实验。本工具分支未另外运行 VLM、SAM、COLMAP 或 3DGS；官方资料读取目前使用已知制造商 URL，几何和力学参数仍有显式先验。

已经验证的内容：

- 原螺丝刀 USD 的电机、制动、反作用及桌面落放实验通过。
- 理想 XYZ 导轨对中、插入和旋松实验通过 32 项检查，约旋转 5.007 圈、退出 4.104 mm，并解除螺纹约束。偏心、倾斜、未接触、错规格和停机对照未错误旋松。
- DSH 0.2.1-alpha.1 实际加载 EnvCreator 插件，并创建 `envcreator-asset` 会话。
- 原生 DSH 已用 `qwen3.7-plus` 实际调用五个插件工具，重新运行理想台架验证并准备 G1 场景；32 项检查通过。模型回复中关于七档离合、批头接口的错误推断单独记录，未计为资产能力。
- G1 抓取/对准工作台已打包，依赖及原生启动参数 dry-run 通过。

尚未验证：自动修改候选资产、G1 接近与抓持、机器人持工具旋松。当前 G1 场景的目标仍为运动学刚体，原生环境尚无电机命令和螺纹交互运行循环。下一轮 DSH 推理待用户提供中转 6.1-sol 的准确接口和独立凭据，不再复用视觉 VLM 密钥；已经完成的 Qwen 预检保持原始模型标注。

## 实验顺序

| 阶段 | 实际任务 | 复用入口与需要补充的内容 | 本轮产物 |
| --- | --- | --- | --- |
| 1. 原生 DSH 执行 | 给模型自然语言任务，让它检查当前工具、查阅资料、实际运行功能验证并解释结果 | 复用 `envcreator-asset` 与 `envcreator_inspect/research/validate/review`；先完成真实模型及插件调用 | 原生会话轨迹、资料、完整正反例实验、模型结论与报告的对照 |
| 2. 生成与失败修复 | 从语言要求生成新候选；在明确的参数错误下检查模型能否定位问题并产生可通过验证的下一版 | 复用 `envcreator_build` 与 Blender/Artisan；补充参数化配方、候选选择与对应验证绑定接口 | 初始候选、失败报告、修改参数、下一版资产与重新验证结果 |
| 3. G1 理想持工具 | 正常重力下，G1 以显式理想夹持持工具，通过原生控制接近目标并尝试旋松 | 加载已有工作台；补充原生环境中的电机命令、啮合/螺纹循环和动态螺丝；标定手掌到工具变换 | 接近、对准、啮合、转动、退出及停止的真实仿真记录 |
| 4. G1 真实抓取 | 从桌面拿起工具，稳定保持，再进行同样的对准与旋松 | 去除理想夹持，复用阶段 3 的工具运行接口；先检查手指包络、摩擦和抓持稳定性 | 抓取与失稳记录、手—工具相对运动、对准和旋松结果 |
| 5. 回到小车连接 | 把已验证的工具和连接模型用于一处固定的小车紧固件 | 重新核对视频证据、批头兼容性、紧固件假设及接近空间 | 一处小车连接的工具操作与连接解除记录 |

第一批先完成阶段 1 和阶段 2 的单一工具实验。阶段 3 开始前先单独确认 G1 能站稳、看见工作台并接近工具区域。各阶段使用有版本的独立运行记录，失败保留。

## 第一轮：DSH 实际调用已有工具

建议公开任务：

> 检查这把电动螺丝刀是否适合当前理想六角螺丝任务，查阅相关资料并实际验证，告诉我它能做什么、哪些情况不能正常工作，以及现阶段能否交给 G1 使用。

任务不指定工具调用顺序，也不把通过用例的数值答案写入提示。部署侧绑定现有资产及运行环境；模型使用插件公开接口。现有验证协议已经固定，模型不能修改检查条件来获得通过。

运行时分别保存：

- 原生 DSH 的实际模型 ID、用户任务、插件调用参数、返回结果与回合结束原因。
- 插件 `call_id`、`agent_id`、前后资产哈希、worker 退出回执及失败文件。
- 实际取得的官方资料、初始场景、六组实验、状态转换及轨迹。
- 模型最终陈述与报告是否一致，尤其是否区分“理想工具验证通过”和“机器人尚未运行”。

`envcreator_review` 只复核已有结果，不能代替这轮要求的实际验证。先完成一次完整的原生调用；出现问题时依据调用记录修订，下一轮使用新版本记录。

## 第二轮：生成与修复的最小范围

当前 `envcreator_build` 使用固定螺丝刀配方，并且新候选不会自动替换绑定资产。因此现有插件接入还不能证明 Agent 已具备自动设计和修复能力。这一轮需要先补充可声明参数的候选生成、候选选择与对应证据绑定接口，仍通过 DSH 插件调用。

先限制在同一工具的三个可解释变量：工作端对边尺寸、TCP 位置和可用电机力矩。分别采用正常候选、批头不匹配、TCP 偏移及不足以克服旋松阻力的候选；一次只改一个因素。环境目标和检查条件保持固定，Agent 从资料和验证反馈修改工具候选。不得靠放宽啮合门限、减小目标阻力或修改判定来修复失败。

保留每一版输入、几何配方、USD、失败和修订。第一轮仅要求证明一个具体失败能够触发正确修订，随后再增加输入和工具类型。其他工具必须有自己的生成器和功能协议。

## 第三、四轮：G1 使用工具

现有工具工作端为 3 mm 对边，理想目标孔为 3.1 mm，对应径向门限约 50 μm。零重力、已知目标坐标的导轨结果不能直接说明 G1 可以靠相机和手臂达到这一精度。

先做两项分开的实验：

1. **显式理想持工具。** 在仿真初始化时声明手掌—工具固定夹持，使用正常重力，验证机器人控制、目标接近及工具运行接口。记录夹持变换，不能称为真实抓取成功。若使用目标真值辅助对准，单列为具有目标真值的理想实验。
2. **真实抓取。** 工具从桌面支架出发，通过接触和摩擦保持。先完成拿起和静止保持，再尝试对准；抓取、插入与旋松分别保留结果。视觉对准优先使用现有相机、深度与机器人状态；若精度不足，需要局部视觉或顺应搜索控制，不能直接放宽门限并沿用原验证结论。

原生环境每个物理步执行 `screwdriving.py` 与 `fastener.py`，DSH 插件提供通用工具电机命令和许可范围内的工具状态读取。高频控制与力学计算在仿真/控制器端运行，模型负责观察、调用和修订操作。解除螺纹后先停机；完整取出与携带螺丝单列为后续行为。

完整机器人实验统一使用本文开头的用户原始任务。接近、对准等单项开发实验另行标注其范围，不能冒充完整任务结果。保持原生相机、控制、停止和回执链；外层记录与评估不代替机器人执行动作。资产开发会话可读取实验报告，机器人评测会话不接收私有判定、目标位姿真值或参考动作，除非该实验明确声明相应观测条件。

## 记录归属与后续范围

每轮保存一个原生 DSH 运行身份。使用已有会话历史和插件日志关联输入、调用、物理记录与结果；继续复用 `integration/smoke.mjs` 的操作前后相机、audit 和停止回执。Blender 轨迹重放与实时仿真录像分别标注。改变资产、模型、观测条件、接触简化或控制方法后创建新版本，原失败不覆盖。

初期保留理想批头耦合与简化螺距模型，研究重点为 Agent 能否通过资料和实际反馈构造可执行工具资产。暂不增加 VLA 训练、高保真螺纹、整车拆装或机械制造合规。等一把工具、一枚螺丝和一次可复查的修复完成后，再扩展工具与连接类型。
