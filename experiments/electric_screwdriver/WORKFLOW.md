# 电动螺丝刀试制记录

日期：2026-10-28。记录可复查的依据、修改和实验结果。

1. **输入和参考。** 用户要求机器人抓持后可独立旋转批头的理想电动工具，并保留真实电动螺丝刀外形。读取 Bosch GO 官方产品页与产品图，选择直柄结构、1/4 英寸六角柄接口。页面未提供可直接采用的工具完整尺寸；尺寸按估计记录，包装尺寸没有被当作产品尺寸。
2. **功能拆分。** 机身包含握柄、电池和减速器的等效外壳；主轴与安装批头独立。开关、照明环及充电口作为固定外观。质量与惯量采用明确先验；机器人通过 API 启动电机。3 mm 工作端是本次选型假设，尚未根据小车凹槽定型。
3. **v1 编译失败。** `outputs/electric-screwdriver-20261028-v1/geometry/build.json` 记录 Artisan 要求连续关节必须传入 effort/velocity limits。新增带证据来源的 Blueprint 数量字段，导出 `MotionLimits(effort=..., velocity=...)`，保持无限角度旋转。没有改成一个大范围有界铰链。
4. **v2 结构检查失败。** `...-v2/geometry/build.json` 报告主轴与机身间缺少支撑，最近间隙约 1 mm。检查后在鼻端补上通孔轴套，轴套与壳体相连，轴套与主轴保留 50 μm 假设间隙。没有降低检查容差或把鼻端孔填实。
5. **v3 通过 Artisan，工具适配失败。** Artisan 将物理 +Y 旋转表达为 joint 的 Z 轴配合两端局部旋转，而工具适配器最初只检查 axis token。修正为检查两端旋转后的有效轴向；保留原始关节变换。另检查到碰撞体以 `col_N` 命名、视觉体以 `vis_N` 命名，不能用原几何体名称推断碰撞形状。最终保留 Artisan 的分块凸碰撞，把视觉体用于正常渲染、碰撞体隐藏。
6. **v4 完成导出。** `...-v4/geometry/build.json` 编译通过；28 个闭合几何体、2 个刚体、1 个连续旋转关节。显式传递塑料、橡胶、钢材类别，添加抓持、轴承与刀尖坐标，创建默认关闭的限力矩速度驱动。生成自包含 USD 和现有 handoff 格式的包。
7. **physics-v1 的统计错误。** 原始轨迹已有正反转与反力，但连续关节坐标回绕使端点相减产生错误累计角度。保留失败报告及轨迹。验证器改为保存原始读数并按相邻实测增量展开，使用角速度积分独立核对累计转角；未改变转动实验阈值、资产或控制输入。
8. **physics-v2 的物理结果通过。** 14 项检查通过，具体数值见 README。实验完成后发现 `sim.stop()` 触发 Isaac Lab 的 STOP 回调，进程持续空转；该次进程通过 SIGTERM 收尾，不能把进程退出码当作物理结果。
9. **physics-v3 验证收尾修复。** 采用公开的回调/实例清理接口，先解除 STOP 回调再停止仿真，随后关闭 App。保持原资产、实验输入和检查条件再次运行，14 项物理检查通过，进程正常退出，退出码为 0。结束后检查没有残留的本任务仿真进程。

可用于后续 Harness 的经验：连续关节必须具备有来源的运行边界；关节轴向要按局部坐标变换解释；运动连接需要有可辨识的支撑结构；视觉体与碰撞体的名称、外形和材质映射需要核实；连续角度必须处理回绕；物理成功、机器人任务成功与进程正常退出分别留存证据。

上述电机台架没有验证真实轴承公差、产品性能、G1 握力或小车螺丝兼容性。以下是后续理想工具—螺丝功能实验，已有小车资产和旧实验代码未被修改。

10. **复用原资产而非另制演示工具。** 从 v4 USD 读取实际机身、主轴、关节与 TCP，保留资产 SHA-256。将旧小车台架中的简化螺纹力学提取到产品模块 `tools/fastener.py`，新增独立六角啮合模型。六角规格、插入深度、轴线、偏心和初始相位决定是否传递等大反向力矩；不直接设置螺丝角度或退出量。
11. **冻结理想范围和反例。** 明确采用零重力、已知目标坐标、受力驱动 XYZ 导轨，以及替代批头接触的理想扭转弹簧。固定六组用例：正常、偏心、倾斜、未接触、错规格、电机关闭。反例除应拒绝旋松外，还检查偏差确实存在；停机反例需要实际插入啮合。
12. **初次运行没有有效报告。** `screwdriver-engagement-20261028-v1` 只留下初始资料。发现 Isaac App 关闭可能吞掉 Python 异常并返回 0，增加 `failure.json`，将“报告存在、门禁通过、进程正常退出”一并作为条件。
13. **资料与运行时失败。** `screwdriver-feasibility-20261028-v2` 记录本机系统 DNS 返回非公网地址，公开资料读取被拒绝；同时 Isaac 重力写入使用整数数组，不能构造 `Gf.Vec3f`。资料读取改用已有的显式公共 DNS 选项，并采用不重定向的官方 `bosch-go-gen3` 地址；重力改为浮点元组。失败目录保留，没有视作通过。
14. **v3 对中失败。** `screwdriver-engagement-20261028-v3/interaction/report.json` 显示 X 偏差仍约 6 mm。检查关节图后确认以 world prismatic 为 articulation 根导致该自由度未生效；新增 world fixed joint → rigid anchor，再接 XYZ 三个移动关节。另发现 12° 旋转最初作用在六角相位而非工具轴倾角，修正旋转组合顺序，并增加实际轴线偏差检查。
15. **v4 理想台架通过。** `screwdriver-feasibility-20261028-v4` 记录官方来源重新获取成功、原资产未修改、32 项检查通过及正常退出。工具在 0.558 s 啮合，螺丝约转 5.007 圈、退出 4.104 mm，11.007 s 解除螺纹约束；五组反例无错误旋松。初始 USD、50 Hz 轨迹、参数、代码哈希和结果完整保存。没有测量真实预紧力，也没有进入 18 mm 完全移除状态。
16. **G1 只做下一步场景准备。** 根据 source-bound 验证制作桌面、工具支架和六角目标；打包依赖与原生启动参数 dry-run 通过。目标暂为运动学刚体，电机关闭，未启动机器人或附着手掌。需要先验证抓取与对准，再将工具命令和交互循环接入原生环境。
17. **可视化与 Harness。** 用生成 Blender 网格重放实际 PhysX 位姿，记录其为轨迹重放。初版微距画面被默认 100 mm 相机近裁面裁掉，缩短到 0.1 mm；重叠支座表面仅在显示网格做并集。`envcreator tool` 现在串联官方资料、已有生成器和功能验证；`tool-test` 可检查现有资产。请求功能验证却未通过时返回非零状态。当前只注册这一种工具，未知工具不能凭名称获得通过结论。
18. **按用户要求接回原生 DSH。** 利用 ClawSpine 已有 `--native-extra-patch` 加载 EnvCreator 普通插件，复用上述后端而非另建 Agent。新增六个相关工具及前后快照、native 调用 ID、失败日志。资产专用 preset 首次对空的全局工具层应用筛选，原生会话创建拒绝；修订为 preset 中注册局部工具后，DSH 0.2.1-alpha.1 实际加载、认证及会话创建通过。失败日志与 v1/v2/v3 配置保留。原生模型回合和 G1 动作未派发；独立台架的历史归属保持不变。
19. **保存用户原始机器人任务。** `public-task.md` 原样保存“让机器人抓握这把螺丝刀 尝试拧松并取下螺丝”。开发阶段不再替换这条完整用户任务，也不额外指定手、坐标、转动圈数或动作脚本。原有抓取/对准准备包保持原记录；螺纹解除与完整取出分别记录，当前未启动机器人任务。
20. **执行前发现环境路径错误。** 检查早期 `dsh-plugin-ready` 实际绑定，项目、OpenUSD、Isaac 模块均无法发现。原因是生成配置时对 Python 使用 `Path.resolve()`，解开虚拟环境符号链接后选择了基础解释器。改为保留虚拟环境启动路径，并用真实符号链接虚拟环境回归验证已安装模块可导入。新配置在 `dsh-plugin-runtime-v2/`；项目、OpenUSD、Isaac Lab、Artisan SDK 的模块发现检查通过，真实后端 `inspect` 与 `review` 正常退出。旧配置不覆盖，台架结果未重跑；该检查不能算原生模型或机器人执行。

21. **原生 DSH 首次执行资产预检。** `run_native_asset.mjs` 只通过原生传输提交自然语言并观察历史。会话 `22208e23-3b95-4f30-b796-1618767e2403` 使用 `envcreator-qwen/qwen3.7-plus`，实际调用 `inspect`、`research`、`validate`、`review` 和 `prepare_g1`；新台架运行通过 32 项检查，退出码为 0。资料、运行报告、前后状态和调用 ID 可对应；原生 DSH 正常退出。记录位于 `outputs/screwdriver-dsh-preflight-20261028-v1/`，机器人完整任务未提交。
22. **模型陈述与实测结果分别核对。** 模型正确指出原生电机/螺纹运行时尚缺、G1 未执行，但将制造商七档离合描述成资产能力，并混淆 1/4 英寸柄接口与 3 mm 工作端。保留原回复，在独立 `review.json` 纠正；不据此宣称完整取出或真实工具性能已验证。
23. **明确模型来源并分开凭据。** 上述 Qwen 是接入时复用了项目 `.env.local` 的视觉 `VLM_API_KEY`，不是 DSH 自带 API。用户提出改用中转 6.1-sol；后续等待准确接口和独立凭据，不继续复用 VLM 密钥或静默回退。历史 Qwen 记录不改标成新模型实验。

24. **独立 6.1-sol 中转接入。** 新增本地私有 TOML 与原生 `llm-pi-ai` 配置适配，未使用 VLM 密钥。参照用户 CC 截图修正为 Responses 协议。旧地址在本机连接失败，v1/v2 原始错误保留；用户更换地址后，`outputs/dsh-gateway-20261028-v3/` 中的原生 `gpt-6.1-sol` 成功调用 `envcreator_inspect`，后端退出码 0，模型读取返回结果并正常结束。该会话只检查资产，没有运行仿真或机器人；图像输入仍未验证。配置入口见 `docs/DSH_MODEL.md`。
25. **动态工作台另建版本。** `prepare_g1_dynamic_workcell.py` 从已验证工具派生动态螺丝场景，保留旧运动学对准包；将原会与轴杆重叠的实心支座改成带 4.5 mm 通孔的四条支座，标明简化螺纹和工具接触替代关系。`outputs/g1-screwdriver-dynamic-20261028-v1/bundle/` 的依赖、三个刚体与一个关节静态打包检查通过。动态螺丝和元数据本身不会执行交互：原生每物理步力学运行、电机命令、重力稳定、G1 抓取与取出仍待接入和实测，没有宣称工具任务就绪。

这一轮可复用的经验是：测试实际交付文件；保留工具与目标的反作用；使用不应生效的真实挑战条件；源资产、数值结果与程序退出分别核对；将理想工具功能和机器人任务证据分开。这里记录的是可复查的工程依据、实验与修订，不将未观测的机械细节当成事实。
