## 参考流程实际做了什么

```text
原视频 → SAM/VLM 与对象多视角证据 → COLMAP 相机
  → 人工角点 + 用户确认的型号族 + 厂商尺寸先验
  → asset_fit.py 多视角拟合和共享尺度
  → prepare() 生成具体构建蓝图
  → Coding → Artisan 编译反馈 → 有界修订
  → 原图照片投影与 Isaac 资产/场景适配
  → 实际 USD 接触、外力矩与支撑测试 → 新进程重载
  → 独立 Review 选择测试 → 冻结蓝图编译 QA → 场景 Review
```

`construction/asset_fit.py::fit_laptop` 用两视角角点拟合尺寸比例、底座倾斜与开合姿态。用户确认 14 英寸 MBP 型号族；Apple 规格页 `https://support.apple.com/en-hk/111902` 的宽度 0.3126 m 用于估计共享尺度，不是现场长度测量。拟合角点 RMS 为约 4.05 px；41 视角笔记本轮廓平均 IoU 为约 0.950。全部视角参与相机估计，不能将该结果称为独立计量精度。

`scripts/build_video_assets.py::prepare` 将约束直接写入蓝图，而不是交给下一阶段重新猜测：

- 两刚体 `base/lid`，质量先验 1.15/0.45 kg；一个被动 revolute 铰链，不固定根、不加电机。
- 底座宽 0.3126 m、深约 0.22161 m，屏幕长约 0.21647 m；厚度与质量分配有明确假设。
- `q=0` 为合盖；子部件坐标系就是铰链坐标系。底座和屏幕的盒体中心明确由自身长度的一半推导，不复制场景坐标。
- 轴为 +X，铰链原点 `(0,0,0.001)`，工作区间 `[0,2.4]` rad 为保守假设；场景初始开角约 128.6° 单独存储。
- 需通过：两刚体与单铰链、允许行程内不穿透、独立支架承托、重力下停留以及外力矩下转动。

旧 `model.py` 的主体几何实际上只有两个 Box。屏幕、键盘的辨识度主要来自真实照片投影；并没有逐键可动机构或精细内部结构。值得复用的是明确的几何/运动约定、观测约束、外观来源和实际验证，不能将更多装饰实体自动视作更真实。

旧独立 Review 的最后有效版本选择 `topology/hinge/clearance`，运行时依据冻结蓝图编译具体断言：部件集合、关节数量、父子关系、轴、原点、范围、被动属性及采样姿态避碰。Review 不能修改候选或物理证据。该旧 QA 编译器仍硬编码 `base/lid` 与一个铰链，只能作为方法参考，不能直接宣称支持任意物体。

## 已验证结果及参考案例的边界

旧场景实际 USD 检查 11/11，通过新进程重载 5/5；笔记本在场景初始角度保持，外加力矩使其转动约 22.9°。这是仿真假设参数下的接触与机构验证。

但后续专项实验明确失败：15°、30°、35°附近释放后继续下落，不支持“所有角度均可悬停”。原蓝图中的 `holds_anywhere` 不能覆盖后来的反例。参考案例应同时收录这些失败与已通过的角度条件，而不是只保存最后一个 PASS。

另有 `outputs/user-g1-contact-20261023-v5/` 的 G1 合盖/拖鼠标记录；这是后续独立机器人接触实验，不能等同于资产生成本身，也不能转移给新生成模型。物理参数、型号代际、隐藏内部和支架均有假设；模型不是对真实整机的完整辨识。

## 建议如何调整 Agent 编排

### 1. 每轮绑定参考方法和本次目标，DSH 继续负责唯一任务循环

将本次找到的记录整理为带哈希的案例索引，包含适用对象/交互、构建方法、输入需求、已通过协议和已知失败。原生 `envcreator_context` 返回匹配案例的简要方法与证据链接；DSH 在本轮计划中记录所选方法及不适用项。

每轮都参照相同的约束与验收流程，而不是给每个新对象复制笔记本坐标、质量或通过记录。同一视频可在明确关联来源后复用用户确认的型号信息；对新视频，这些仍是待核对先验。参考案例与当前观测使用不同来源角色，不能绕过现有同任务产物绑定。

DSH 自动推进正常步骤；EnvCreator 提供事实、约束和可执行检查。无需人逐次批准工具，也不另建外层模型循环。提示词中的顺序只是说明，工具前置条件和产物约束才负责保持执行质量。

### 2. Blueprint 前补观测拟合，Blueprint 后冻结可构建的约束

建议增加内部 `fit/calibrate` 操作，将真实相机、掩码、像素关键点、可适用的资料先验及人工补充转成带误差和来源的尺寸/姿态约束。已有 `asset_fit.py` 可复用算法思路，但其笔记本类别、世界位置范围和标注输入均有专用假设，需要参数化；不能只包装原脚本就称为通用拟合。

没有绝对尺度时允许相对拟合和显式仿真假设，不伪造实测；本次已知产品尺寸应标为资料先验，不能塞进人类实测 `measurements`。现有 research 来源应参与适用性核对。

保留语义 Blueprint，再形成通过审核的构建约束：尺寸及容差、父子坐标变换、关节轴与零位、场景初始姿态、被动属性、支撑接口、碰撞意图和具体验收条件。未知值可保留，但用于编译的默认值必须显式记录为仿真假设；无法支持请求交互时返回缺口，不能以 schema 合法代替任务完成。

### 3. 先完成可用机构，再补真实可见外观

建议顺序为：

```text
context/参考方法 → perceive → evidence/scope
  → 必要的 research、相机与观测拟合
  → Blueprint + 构建约束 → 独立结构审核
  → 主体几何/运动零位检查 → build → 自动编译具体 QA
  → 实际物体外观与机构审核
  → 原图投影/必要的可见细节 → 重查受影响项
  → scene → 请求交互对应的 physics → 新进程 reload → task_review/export
```

对于笔记本，先得到两刚体、单被动铰链、合盖零位及允许开合范围内的合理接触，再添加屏幕/键盘照片投影和有依据的细节。可见铰链需要合理几何，未观测内部不要求虚构。背景 COLMAP/3DGS 是并列产物，其完成不能替代物体分支通过；本轮不实施并发。

### 4. 修订接收“证据 + 当前状态 + 精确缺陷”，并按缺陷回到对应阶段

内部几何调用增加与候选 SHA 匹配的正面、侧面、近景实际渲染、坐标轴/包围范围，以及精简的具体 findings。让运行时计算旋转后的轴、父子变换和间距，不依赖模型的自然语言自证。

不同问题走不同修订路径：身份/对象范围回到语义；证据不足回到拟合/资料；零位与关节变换回到构建约束；局部断连回到几何；纹理回到外观；USD 丢失状态回到导出适配；缺运行时单独报告。测试协议错误与物体缺陷分开，不能重建物体来掩盖测试器错误。

局部修订冻结已通过且仍适用的约束，保留缺陷与变更差分。相同数值错误连续出现时应改变表示方式，例如使用“沿主体边缘对齐”的几何关系，而不是反复补一句提示词。同一问题建议限定几次有效修订后保存未完成结果；不能靠删验收项或调整通过阈值结束。

### 5. 将人工验收要求变成候选不能改写的检查

将旧 `compile_review_qa` 的做法迁移到当前通用 schema：按实际部件/关节生成检查，不再硬编码笔记本名称。具体覆盖部件与关节集合、q=0 形态、轴/连接关系、同刚体连通、运动间隙、质量/尺寸来源、支撑与场景约束。VLM 独立审核用于核对语义和图像；数值与几何条件由程序执行。

功能通过必须绑定当前模型、导出 USD、协议版本和实际运行条件。笔记本测试至少区分无驱动基线、小力矩不应转动、足够外力矩的正确方向转动、释放、限位和不同开角；沿用旧小开角失败作为需要复查的回归案例。作用必须施加到正确刚体，局部轴根据实际姿态转换到世界轴；当前 `_verify` 明确假设局部轴与世界对齐，应在倾斜或旋转场景中取消该简化后再验收。

独立重载检查应针对冻结导出的场景，不追加隐藏初始化修复。GUI 继续只展示结构图、真实渲染、简短缺陷和验证条件，完整机器约束留在内部产物中。

第一次尝试仍用同一电脑原视频：验证自动编排能得到一致的零位、连通模型、可见外观、实际交互与重载证据；记录它复用了哪些旧事实、自动产生了哪些新约束、还需要哪些人工输入。随后用自行车检查这套编排是否能按新机构生成约束，避免把笔记本专用模板误当作通用能力。

本规划没有实施。当前参考记录保持原样；不把旧资产通过、旧真值坐标或旧人工标注改记成本轮自主识别成绩。
