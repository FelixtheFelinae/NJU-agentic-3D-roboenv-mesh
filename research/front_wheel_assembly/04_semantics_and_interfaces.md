# Assembly Semantics、Interaction Model 与接入位置

本文件列出拟新增的数据和模块职责，不是已经存在的 API，也没有给现有代码增加字段。

## 1. 用连接图补充部件树

现有 `Blueprint.parts/joints` 适合记录运动层级；紧固关系应另用连接图表示。一枚外侧螺母可通过垫圈夹持叉端和支架，不能只写成“螺母是轮轴的 child”。运动关节、紧固边、接触、支撑和工具啮合也不能统一成同一种 `fixed` 关系。

首轮的语义记录至少分成：

| 记录 | 拟包含内容 | 主要检查 |
| --- | --- | --- |
| `PartRef` | 资产快照、稳定部件 ID、局部坐标、实际刚体/几何引用 | 身份和来源哈希一致；不存在的模型件不能进入连接 |
| `Interface` | 所属零件、局部原点/轴线、面或几何区域、候选工具接触面 | 轴为单位向量、坐标转换明确、接口位于有效几何附近 |
| `ThreadedConnection` | 轴与目标螺母、夹持堆叠、对偶接口、旋向、导程、有限啮合区 | 配对身份、同轴性、堆叠及剩余啮合能计算 |
| `Retention/Attachment` | 另一侧保持件、候选止退、制动或附件连接 | 其作用是夹紧、几何保持还是附属连接，不能从名字猜定 |
| `ToolInterface` | 扳手/套筒类别、匹配尺寸、接近坐标、咬合范围、操作包络 | 不只检查轴线可到达，还检查工具头和手柄 |
| `Fixture/Support` | 抗转对象、承托对象、固定前叉、允许自由度、启用阶段 | 不把实验夹具误算作实车结构；释放实验不保留意外约束 |
| `ActionDependency` | 前置条件、受影响连接、执行后可观测条件、条件分支 | 区分全部满足/可选分支；未知不能自动当作已满足 |

局部接口既记录原点，也记录轴向约定及参考姿态。零件坐标经 USD 适配改变时，要重映射接口和连接引用；不能只重映射视觉网格。

## 2. 来源、假设与人工修正

每个结构关系和参数保存“值或候选集合、单位、来源类型、证据引用、理由、当前状态”。来源至少区分图像观察、型号匹配的外部资料、几何计算、实测、建模假设和人工指定。

以下字段在本车当前证据中仍需保留未知或备选：

| 字段 | 当前处理 | 后续可用的修正依据 |
| --- | --- | --- |
| 轴端普通螺母/防盗端帽/快拆 | 不确定；首例单独选择普通螺母假设配置 | 两侧近拍、型号或拆解记录 |
| 内部锁紧螺母与外侧保持件的身份 | 不混同 | 局部结构与维修资料 |
| 叉端开口、止退唇、垫圈堆叠 | 不确定 | 叉端近拍和已知配合几何 |
| 轴径、导程、旋向、有效啮合量 | 使用有版本的实验先验时标 `assumed` | 实测、匹配型号规格，或专门标定 |
| 松脱/运行阻力、预紧代理 | 不从外形推成已知 | 真实力矩—角度/轴向运动数据 |
| 制动、线缆、挡泥板依赖 | 条件分支，不能默认已解除 | 连接端点与实际拆卸证据 |
| 工具尺寸及可用方向 | 几何候选 | 工具规格和全包络空间检查 |

“人工指定”不自动等于“实测”。人工修正接口应能选择连接候选、调整局部轴线、替换工具、填写参数、修改条件依赖，并逐字段保存修改者、来源、时间、旧值和新值。修改后重算受影响的几何/工具/交互检查；原始 Agent 提议保留。

这不是逐次请求用户批准的流程。可在所选假设配置内自主运行研究夹具，但报告必须标明条件范围；不能把未确认的实车关系默认为已确认。若目标是完整实车拆轮，关键分支未知会保留为未解决。

## 3. Agent 做什么，确定性程序做什么

| 环节 | Agent 的工作 | 可计算或执行检查 |
| --- | --- | --- |
| 连接候选 | 根据图像、零件、接口和资料提出可能连接及备选 | 身份、局部坐标、同轴/邻接、接口大小与证据引用 |
| 工具与顺序 | 提出工具类别、操作方向、必要先决条件 | 接口兼容、操作包络、条件依赖完整性和冲突 |
| 模型参数 | 说明需要哪些参数及来源；选择显式先验 | 单位、正值/有限值、边界与配置版本；不允许测试中静默改变 |
| 编译 | 选择受支持的交互模型类型 | 受信任编译器构造初态、约束、工具代理和事件规则 |
| 验证 | 根据失败证据提出结构或参数修订 | 独立验证器核对轨迹、条件、解除事件和分离；不由生成者自报成功 |

几何接近不保证真实紧固，VLM 的 `PASS` 也不能替代可计算检查。前一轮 Harness 已出现肩部外形误判，因此新增连接语义也不应只依赖第二次模型调用确认。

Agent 解释的“这是螺母”与运行时“已脱扣”属于不同层面。状态转换只由冻结规则和实际测量驱动；验证器重新检查事件条件，不能简单读取 `removed=true`。

## 4. 拟新增组件与已有模块的边界

下表中的新名称都是职责建议，具体文件名和实现方式留到获准实施后确定。

| 拟新增组件 | 输入 → 输出 | 复用位置 |
| --- | --- | --- |
| Assembly 数据契约 | 部件/接口/来源 → 连接图、条件依赖、假设配置 | 参考 `construction/contracts.py` 的类型约束与来源记录 |
| Assembly 推理与复核 | 原始证据、候选几何 → 有来源的连接候选及未解决项 | `construction/evidence.py`、`design.py`、`harness/research.py` |
| 接口几何与工具空间检查 | 连接候选、实际 mesh、工具包络 → 可用候选或具体冲突 | 复用 Blender 产物、坐标和碰撞依赖，不以预览图代替 |
| Interaction 编译器 | 选定连接假设和冻结参数 → 初态约束与运行配置 | `harness/geometry.py` 的受限数据生成、Artisan 导出及 USD adapter |
| Assembly runtime | 约束、工具代理、力/力矩输入 → 仿真状态与约束事件 | 独立 Isaac worker；复用现有进程隔离、日志和报告落盘 |
| Assembly 验证协议 | 原始模型、冻结协议、轨迹与事件 → 分项结论及反馈 | `harness/physics.py` 的哈希/协议核验、`task_scope.py` 的同对象证据绑定 |

先在独立前轮实验调用这些职责，不立即改整车默认构建入口。新协议实际存在前，现有 rotary/coupled 通过不能覆盖 threaded_fastener/assembly_release。

## 5. 三个后端问题必须先实验

1. **跨域耦合**：Artisan SDK 的 `turns` 有表示入口，本仓库包装未暴露；本机 USD/Isaac 是否正确处理旋转—直线、角度单位和反作用，尚无运行证据。
2. **可分离刚体**：优先研究把可拆保持件作为独立刚体，以外部约束连接，避免要求 reduced-coordinate articulation 在运行中删 link。是否需要关节重建、是否连续保留速度和碰撞，都需记录，不预设热切换成功。
3. **完整释放**：取消螺旋关系并不自动解除其他 guide、固定关节或碰撞屏蔽。需按状态核对实际约束集合，并以拉离运动验证。

可用性试验只要发现单位错、约束无效或速度突跳，就应把问题留在后端层；不能调低几何分离要求、直接写姿态或删除障碍来绕过。

## 6. 未来产物如何留下证据

未来的资产包除 USD 及依赖外，还需包含：

- 原始证据和基线资产指纹、稳定部件/接口引用；
- 原始连接候选、采用/拒绝原因、显式假设和人工覆盖记录；
- 初始装配图、工具/夹具配置、冻结交互参数和测试协议；
- 实际力矩/力、相对位姿与角速度、有效啮合量、约束启停事件；
- 独立工具空间、保持、脱扣、分离和条件依赖检查；
- 失败候选与局部修复记录，不覆盖之前未通过的结果。

原始 USD 保持不变。运行时在独立状态层改变约束，保存事件触发值和前后约束引用；必要的重建或速度映射必须显式记录。视觉展示、运动学演示、简化动力学验证和实车证据分别标记，不能共用一个模糊的“拆卸成功”。
